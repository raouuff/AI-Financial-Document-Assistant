# AI Financial Document Assistant

An AI agent that automates the processing and organization of project financial
documents: it reads uploaded invoices/receipts (PDF or image), extracts the key
fields with an LLM, categorizes the expense, **validates** the data (missing
info, inconsistent entries, duplicate invoices), stores it in an organized
expense tracker (SQLite + one-page dashboard), and produces a **financial
summary by category and currency** — with one-click CSV/Markdown exports.

> Built for the "AI-Powered Financial Management" take-home task, Part 1.
> All sample data is fictional. No confidential financial information,
> credentials, or personal data is included.

## 🚀 Quick start (60 seconds)

```bash
# 1. create venv + install
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. (optional but recommended) configure the real LLM
cp .env.example .env               # then paste your key:
#   GEMINI_API_KEY=...  ← free at https://aistudio.google.com/apikey

# 3. run
python run.py                      # → http://127.0.0.1:8000
```

Open **http://127.0.0.1:8000**.

### Test without an API key (demo mode)

The app boots in **demo mode** when no `GEMINI_API_KEY` is set. It ships with 10
fictional sample documents in `sample_data/` (generated by
`scripts/make_samples.py`), pre-baked with realistic extractions — including a
**duplicate invoice pair**, a **receipt with a missing date**, and a
**suspected same-day repeat charge** — so every validation rule can be
observed firing:

| Sample file | Category | Currency | What it demonstrates |
|---|---|---|---|
| `invoice-software-subscription-usd.pdf` | software | USD | Clean invoice → extraction with no flags |
| `receipt-office-supplies-egp.png` | operational | EGP | Receipt without invoice number → *missing* (info) flag |
| `invoice-hotel-travel-eur.png` | travel | EUR | Clean multi-line invoice |
| `invoice-hotel-travel-eur-COPY.png` | travel | EUR | Second upload flagged **duplicate** → rejected (approval step) |
| `receipt-event-catering-usd-nodate.png` | events | USD | Missing date → *missing* (error) flag; fixed inline in the tracker |
| `invoice-equipment-camera-badvat.png` | equipment | USD | VAT ≥ total → *inconsistent* flag; approved with the warning visible |
| `invoice-personnel-contractor-usd.pdf` | personnel | USD | Clean contractor invoice |
| `receipt-taxi-travel-usd.png` | travel | USD | Small travel receipt (exercises the duplicate heuristic) |
| `receipt-taxi-travel-usd-same-day.png` | travel | USD | Same vendor + amount + date → **potential duplicate** flag; human review decides it is legitimate (false positive) |
| `invoice-rent-operational-aed.png` | operational | AED | Fourth currency exercised in the summary |

In real mode those same samples are processed through actual Gemini calls.

## 🖥️ Using the dashboard

1. **Upload & Process** — drag any PDF/PNG/JPG invoice or receipt. The extracted
   record is shown with all flags.
2. **Expense Tracker** — every record lands here automatically. Fix any flagged
   field inline and hit **Save** (the agent re-validates automatically and
   clears flags that were resolved), then **Approve** or **Reject**.
3. **Financial Summary** — expenses chart by category (segments colored by
   currency), totals by category and currency + downloadable
   `financial_summary.md`.
4. **Export CSV** — downloads the full expense tracker sheet.

## 🔌 API (OpenAPI docs at `/docs`)

| Endpoint | Purpose |
|---|---|
| `POST /api/upload` | Upload → extract → categorize → validate → store |
| `GET /api/expenses[?status=]` | List the tracked expenses |

## ⚙️ How extraction works (real mode)

Gemini is called with the raw file bytes (it reads PDFs and images natively —
no OCR pipeline needed) together with a prompt + a **strict JSON schema**
(`response_schema`), so output is always parseable. Dates are normalized to
`YYYY-MM-DD`, currency to ISO codes, and the model must return empty fields
rather than invent ones — feeding the validation flags.

## 🗺 Suggested evaluation walkthrough

A review session that exercises every requirement in ~10 minutes:

1. **Upload & extraction** — process `invoice-software-subscription-usd.pdf`;
   confirm all fields (date, vendor, invoice #, description, amount + currency,
   VAT) and the `software` category with no flags.
2. **Duplicate detection** — upload `invoice-hotel-travel-eur.png`, then its
   `COPY`. The copy is flagged as a potential duplicate with a link to the
   original; **Reject** it (the tracker's `status` column records the decision).
3. **Missing information + human correction** — upload
   `receipt-event-catering-usd-nodate.png` (missing date flag); type
   `2025-12-14` into the tracker, press **Save** (record re-validates and the
   flag clears), then **Approve**.
4. **Inconsistent data** — `invoice-equipment-camera-badvat.png` carries a
   VAT-not-smaller-than-total warning into approval, demonstrating
   approve-with-warning for human judgment.
5. **Judgment calls** — upload both taxi receipts; the second is flagged
   `potential duplicate` although both rides are legitimate — approve both to
   show why a human remains in the loop.
6. **Summary & outputs** — open the Financial Summary tab (stacked chart by
   category, per-currency totals), then export the CSV and the Markdown
   summary; reference `/docs` for the API contract.

## ⚠️ Limitations (for reviewers)

- **Currency conversion** is out of scope: totals are shown per currency, no
  FX rates applied.
- LLM extraction can be wrong on blurry photos/complex layouts; that's why the
  pipeline always routes records through **human review** with flags.
- Demo mode replays pre-baked extractions for the bundled samples only; real
  documents require the API key.
- Duplicate detection is heuristic (vendor+invoice #, file hash, or
  vendor+amount±3days) — can miss clever duplicates or false-flag refunds.
- No authentication — intended as a prototype behind `localhost`.
- Hebrew/Arabic RTL documents were not part of the tested sample set.

## 🛠 Troubleshooting

| Symptom | Fix |
|---|---|
| `No GEMINI_API_KEY configured` on a real upload | Add the key to `.env` and restart |
| 415 on upload | File must be PDF/PNG/JPG/WEBP ≤ 15 MB |
| Port already in use | `PORT=8001 python run.py` |
| Reset everything | Stop the app, delete `data/` |
